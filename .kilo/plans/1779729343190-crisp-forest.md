# Ceylon Track — Major Overhaul Plan

## Findings from Codebase Audit

### Current State
- **16 HTML pages** with 4 different design systems (blue/navy, green, dark dashboard, purple)
- **No WebSocket** — all real-time data via REST polling (5s intervals)
- **10 mounted route modules** under `/api/`, no WebSocket server
- **GPS Demo** (`gps-demo.html`) linked from 6 pages — needs removal
- **Demo map** (`map.html`) uses hardcoded station data and raw `fetch()` — needs removal
- **Timetable bug**: joins `sri_lanka_timetable` with stations — may fail if `start/end_station_id` is NULL; no loading spinner between calls
- **`ceylon-track-admin` role does not exist** — current schema only has `passenger`, `staff`, `admin`
- **No staff approval workflow** — staff signup is immediate
- **Theme system**: pages use different CSS variables, fonts, and color schemes — 4 distinct themes co-existing

### DB Schema Gaps
- `users` table missing: `status` (pending/active/suspended), `theme_preference`, `approved_by`, `approved_at`
- No `live_train_sessions` table for GPS tracking session management
- No `staff_management` infrastructure

## Phase 3: WebSocket Infrastructure

### 3.1 Install `ws`
```bash
npm install ws
```

### 3.2 Create `backend/websocket.js`
- Wraps the Express HTTP server with a WebSocket server on the same port
- Manages connected clients with a Map<ws, { userId, role, subscribedTrains }>
- Handles these message types:
  - `gps_update` — staff broadcasts location → stored in DB + broadcast to all subscribers
  - `subscribe_train` — client subscribes to a specific train's updates
  - `unsubscribe_train` — client stops watching a train
  - `session_started` — staff begins sharing session
  - `session_ended` — staff stops sharing session
- On WebSocket disconnect: if client was a staff member with active session, mark train offline after 30s

### 3.3 Integrate with `backend/index.js`
```javascript
const { createServer } = require('http');
const { setupWebSocket } = require('./websocket');
const server = createServer(app);
setupWebSocket(server);
// Replace app.listen() with server.listen()
```

## Phase 4: Share Location Feature

### 4.1 Frontend — `frontend/js/gps-broadcast.js` (new shared module)
- `requestGPSPermission()` — calls `getCurrentPosition()` to trigger native prompt
  - Returns `{ granted, error }` based on result
- `startGPSWatch(onUpdate, onError)` — calls `watchPosition()`, returns watchId
- `stopGPSWatch(watchId)` — calls `clearWatch()`
- `requestWakeLock()` / `releaseWakeLock(wakeLock)` — screen sleep prevention

### 4.2 Frontend — `staff-app.html` changes
- Add "Share Location" button to navbar (replaces GPS Demo)
- Click → GPS permission check → train selection modal → start sharing
- Active sharing banner at top: live accuracy, speed, [Stop Sharing] button
- Hidden for `sub_role === 'station_master'`
- On page load: detect existing active session via API → offer "Resume Sharing"

### 4.3 Train Selection Modal (built into staff-app.html)
- Fetches active schedules from `/api/schedules/search`
- Staff selects one train from dropdown
- Backend validates: no other active session for this train
- Backend validates: staff is on assigned route (if assignment exists)

### 4.4 Backend — `routes/sessions.js` (new)
- `POST /api/sessions/start` — create live_train_sessions record
- `POST /api/sessions/stop` — mark session inactive
- `GET /api/sessions/active` — return active sessions for Live Map
- `GET /api/sessions/my-active` — get current staff member's active session (for resume)

### 4.5 WebSocket Flow
```
Staff Browser                    Backend WS                All Subscribers
     |                              |                            |
     |-- ws: session_started ------>|                            |
     |                              |-- query active sessions -->|
     |-- ws: gps_update ----------->|                            |
     |                              |-- store in DB              |
     |                              |-- broadcast gps_update --->|
     |                              |                            |-- update marker on map
     |-- ws: session_ended -------->|                            |
     |                              |-- mark train offline       |
     |                              |-- broadcast offline ------>|
```

### 4.6 Security Rules
- Only `role === 'staff'` with `sub_role !== 'station_master'` can initiate
- Unique constraint: one active session per schedule_id per day
- Unique constraint: one active session per staff_id at a time
- SQL validation of train existence and staff authorization

## Phase 6: Timetable Bug Fix

### 6.1 Root Cause Investigation
The `timetable.html` page issues:
1. `api.updateNav()` and `api.getTimetables()` both called on `DOMContentLoaded` — potential race
2. API call may silently fail if database has NULL `start_station_id`/`end_station_id` values
3. No loading spinner between dynamic nav update and data load — confusing UX
4. Error message shows but offers no retry mechanism

### 6.2 Fixes
- Add null-safe JOIN in `routes/timetable.js` (use LEFT JOIN, COALESCE station names)
- Add loading spinner that persists until data renders
- Add retry button on error state
- Always render timetable table (even empty) — never show blank page
- Add `window.addEventListener('load', ...)` as fallback if DOMContentLoaded fires too early

## Phase 7: Unified Theme System

### 7.1 Create `frontend/css/theme.css`
Define 4 themes using CSS custom properties on `body[data-theme="..."]`:

| Theme | `data-theme` | Background | Primary | Accent | Surface |
|---|---|---|---|---|---|
| Dark Navy (default) | `dark-navy` | `#0A0F1E` | `#1B6CA8` | `#00B4D8` | `#111827` |
| Midnight Black | `midnight` | `#000000` | `#06B6D4` | `#22D3EE` | `#18181B` |
| Light Clean | `light` | `#F8FAFC` | `#0F4C75` | `#00B4D8` | `#FFFFFF` |
| Sunset | `sunset` | `#1C1917` | `#F59E0B` | `#F97316` | `#292524` |

Variables defined: `--bg`, `--surface`, `--surface-2`, `--text`, `--text-2`, `--border`, `--primary`, `--primary-2`, `--accent`, `--accent-2`, `--success`, `--warning`, `--danger`, `--shadow`, `--font-body`, `--font-display`

### 7.2 Refactor Every Page
Replace every `<style>` block's `:root` and `[data-theme]` definitions with:
```html
<link rel="stylesheet" href="/css/theme.css">
```
Apply theme variables consistently:
- `background-color: var(--bg)` instead of hardcoded colors
- `color: var(--text)` instead of hardcoded text colors
- `var(--primary)` for buttons, links, highlights

Pages to refactor: All 15 remaining HTML files (after removing gps-demo.html and map.html)

### 7.3 Theme Detection Script
```html
<script src="/js/theme-loader.js"></script>
```
Loads user's theme from `api.getUser().theme_preference` before page render:
1. On login: store theme from API response → apply immediately
2. On page load: check `localStorage` cache → fallback to `dark-navy`
3. Prevent flash of wrong theme by running script BEFORE `</head>`

### 7.4 Theme Loading Flow
```
Login → API returns user { theme_preference: "sunset" }
  → Store in localStorage + apply to document
  → All subsequent pages read localStorage before CSS paints
```

### 7.5 Settings Page — `frontend/settings.html` (new)
- Theme selector with 4 radio cards (preview of each theme)
- "Save Theme" button → `PUT /api/users/theme` → stores in DB + localStorage
- Accessible from: all role navbars
- Shared across roles — no special permissions needed

### 7.6 Backend — `PUT /api/users/theme`
```javascript
router.put('/theme', authenticate, async (req, res, next) => {
  const { theme } = req.body;
  // Validate against allowed themes
  await pool.query('UPDATE users SET theme_preference = $1 WHERE id = $2', [theme, req.user.userId]);
  res.json({ success: true, theme });
});
```

## Phase 8: Role System Overhaul

### 8.1 New Role: `ceylon-track-admin`
- Role value in DB: `ceylon-track-admin`
- Seeded via migration 005 (NOT publicly registerable)
- Full access to admin panel

### 8.2 Staff Approval Workflow

**Signup flow:**
1. Staff fills registration form (employee_id, staff_access_code, sub_role)
2. Account created with `status = 'pending'`
3. Response: `{ message: "Your registration is pending admin approval.", status: "pending" }`
4. Staff CANNOT log in until `status = 'active'`

**Admin approval flow:**
1. Admin views staff management page
2. Sees all staff with status filter (pending/active/suspended)
3. "Approve" button → sets `status = 'active'`, `approved_by = admin.id`, `approved_at = NOW()`
4. "Reject" button → prompts reason, sets `status = 'suspended'` with `rejection_reason`

### 8.3 Admin Dashboard Pages

**`frontend/admin.html` — Refactored as true admin panel:**
- Staff Management tab: table of all staff (name, emp ID, status, actions)
- Schedule Management tab: CRUD for static timetables (delegates to public/manage-schedules.html or embeds)
- Live Map (read-only, embedded or linked)

**`frontend/admin/manage-staff.html` — Staff Management (new):**
- Filterable table: name, email, emp_id, role, sub_role, status
- Approve/Reject buttons for pending staff
- Suspend/Reactivate buttons for active staff
- Rejection reason shown in tooltip

### 8.4 Login Page Changes
- Role dropdown: Passenger / Staff / Ceylon Track Admin
- Staff uses employee_id + staff_access_code
- Pending staff get "Your account is pending approval" message
- Ceylon Track Admin uses email + password

### 8.5 Navbar Per Role

**Passenger:**
`Search` | `Live Map` | `My Watches` | `Settings` | `Logout`

**Staff:**
`Search` | `Live Map` | `My Watches` | `Share Location` | `Settings` | `Logout`

**Ceylon Track Admin:**
`Live Map` | `Staff Management` | `Schedule Management` | `Settings` | `Logout`

### 8.6 Route Guards
All pages must call `api.requireRole()` or `api.requireAuth()` before rendering:
- `live-map.html`: public (all roles including unauthenticated)
- `index.html`: public
- `timetable.html`: public
- `watch.html`: authenticated only
- `staff-app.html`: staff role only
- `admin.html`: `ceylon-track-admin` role only
- `admin/manage-staff.html`: `ceylon-track-admin` role only
- `settings.html`: authenticated only
- `station-setup.html`: staff with `sub_role=station_master` only
